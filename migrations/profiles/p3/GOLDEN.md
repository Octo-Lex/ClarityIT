# P3 Golden Profile

The golden manifest (`golden-manifest.json`) is the expected result of capturing
the P3 fixture. It is produced by `scripts/profile/validate_p3.py --update-golden`
which applies `schema.sql` + `seed.sql` to a fresh PostgreSQL container pinned by
digest, captures the profile, and writes the golden.

## CI verification

CI runs `validate_p3.py` (without `--update-golden`) in verify-only mode.
Both fresh captures must:
1. Be self-consistent (stored == recomputed).
2. Be deterministic (A == B).
3. Equal the committed golden fingerprint.
4. Pass the 12-pattern secret + production-identifier scan.

Missing golden is a hard failure (only `--update-golden` can establish it).

## Byte-determinism

`generate_p3.py` is byte-deterministic: identical P1 input produces identical
`schema.sql` and `seed.sql` bytes (no embedded timestamps).

## What P3 is NOT

- Not a resolution of migrations 016/018/029 (G2 work).
- Not a competing 005/018-shaped variant — it represents the single captured P1 source shape.
- Not production evidence — it is a CI/conformance fixture.
