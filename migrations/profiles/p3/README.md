# P3 — Sanitized CI Legacy Fixture

A deterministic, entirely synthetic legacy database fixture matching P1's schema
shape, seeded with minimal legacy-truth cases for later migration classification
tests. **Free of all production rows, identifiers, credentials, hostnames, and
infrastructure details.**

## What P3 is

- Generated by `scripts/profile/generate_p3.py` from the P1 production manifest's
  structural metadata (tables, columns, types, constraints, indexes, functions,
  triggers, sequences).
- Represents the **single captured P1 source shape**.
- Seeded with 11 synthetic rows (6 bootstrap + 5 legacy-truth cases) exercising
  the classifications (Migration spec §6.1): `agent_effect_results.status='succeeded'`,
  `asset_actions` with `proxmox_task_id`, `asset_actions` executing,
  `approval_requests approved`, `action_outcomes`.

## What P3 is NOT

- Not a resolution of migrations 016/018/029 — that is G2 work.
- Not a competing 005/018-shaped variant.
- Not production evidence — it is a CI/conformance fixture.

## Files

| File | Purpose |
|---|---|
| `schema.sql` | Synthetic DDL matching P1 shape (64 tables + sequences + functions) |
| `seed.sql` | Minimal legacy-truth seed rows (11 synthetic rows: 6 bootstrap + 5 truth cases) |
| `golden-manifest.json` | Expected capture manifest (the golden profile) |
| `GOLDEN.md` | Fingerprint reference + validation proof |

## Golden fingerprint

`cedf689db8e890eeb48a3d3c8e9d0255db8399641b7be1732e67491ec2f1407b`

Proven: self-consistent, deterministic (two captures match), secret-scan clean,
matches committed golden. See `GOLDEN.md` for details.

## Regenerating

```bash
python scripts/profile/generate_p3.py \
    --p1-manifest <path-to-p1-manifest.json> \
    --output migrations/profiles/p3/
```

The P1 manifest is in the external evidence store (not in this repo). The
generator is deterministic: same manifest → same `schema.sql` + `seed.sql`.
